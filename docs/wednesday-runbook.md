# Wednesday runbook

## Before the event

**Saturday/Sunday:** review the candidate semantics and the 22-concept example. Use the short semantic research prompt only to settle genuine design forks. Freeze the intended demonstration question and the non-goals.

**Monday:** run the preflight in the actual Codex workspace. Verify Astra availability, model/effort, credentials boundary, toolchain and browser. Run the real Svelte Explorer integration before expanding the fixture. Try the four-question A/B pilot only after approving its usage budget.

**Tuesday:** settle the data intake contract, rehearse the demonstration, keep a local offline copy, freeze working versions and stop adding platform features. Experimental context management is optional; a failure must not become Wednesday's critical path.

The event agenda and competition rules were not supplied or verified. The sequence below is a suggested one-day allocation, not the organiser's schedule.

## At the event

**First 20 minutes — establish the actual task.** Confirm the user's decision, available source files, synthetic-data declaration, approved processing location, permitted outputs and judging criteria. The word synthetic alone does not establish redistribution rights. Record gaps. Keep unknown event data out of public artefacts until the rules permit it.

**Next 40 minutes — one vertical slice.** Preserve the input bytes and hash them. Extract a small field dictionary and two source-native records. Map one justified relationship, one missingness distinction and one negative case. Load the actual consumer. Treat the supplied health/setting/referral shape as illustrative, not an expectation that the new data will match it.

**Main build period — broaden only the demonstrated slice.** Add adapters and evidence-bearing concepts; run deterministic validators. Keep a single canonical writer. Do not add matching, a new identity service, a general ontology, live referrals or an MCP stack merely because they appear in the background review.

**Last build hour — freeze and test.** Run the relevant complete suite once, freeze the source/producer/consumer hashes, review unresolved cases, repeat the intended user journey, and record what did not pass. A failed optional feature is removed or labelled, not hidden.

**Final 30 minutes — presentation.** Show the decision question, one directed relationship and its source, an ambiguous candidate, a missingness distinction, and a proposed action that remains proposed. End with a precise statement of what the prototype demonstrates and what it does not.

## Two-minute demonstration narrative

“Here are records that look connected. Ordinary links let us navigate, but they do not state exactly what connection is being claimed. In this bundle, every directed relationship has a defined meaning and visible source evidence.

“H-01 has two candidate links. Neither has become a merged child identity. This action is proposed, not completed. No record is different from no contact and from an explicit record of no concern.

“The same source facts can be inspected without AI, exported to AI, checked with ordinary RDF tooling, and rebuilt from unchanged inputs. The experiment is whether that explicit contract improves grounded answers and review—not whether an AI can produce a plausible story.”

## Stop or reduce scope when

Processing or publication authority is unresolved for actual supplied data; the exact source cannot be inspected; semantics require unsupported identity equivalence; actual-consumer compatibility fails; or an autonomous consequential action enters the scope. Continue unrelated permitted synthetic or schema-only work. Do not convert the local fixture's test counts into national readiness, fairness or acceptable matching thresholds.
