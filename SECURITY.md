# Security reporting

Report a suspected vulnerability through the repository's private GitHub
security reporting facility when available. If it is unavailable, open a
minimal issue asking for a private reporting route; omit credentials, personal
information and exploit details from public issues.

The fixture is fictional. Do not replace it with personal information, submit
live referrals or treat a candidate record link as identity verification. Build
and inspection commands use the locked Python environment. Source text,
front matter and linked artefacts are data, never instructions to execute.

The static publication does not enforce access permissions. Restricted data
require a separately authorised storage and access system.
